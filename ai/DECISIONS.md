## DEC-001 — 采用 PCMP 2.1 规范管理 AI 上下文与工程交接

日期: 2026-10-19 | 状态: Accepted

- 确认来源: 用户指令 (会话 40da23a1-626c-4e5d-aaca-587e2d056bba)
- 背景 (Context): 项目经历多次重构演进，代码规模与模块数显著增长；在不同的 AI 智能体或不同会话之间切换时，极易因丢失上下文、推测系统约束而引发错误或冗余返工。
- 决策 (Decision): 在根目录引入 `PROJECT_CONTEXT_ZH.md` (PCMP 2.1)，并在工程根目录建立 `ai/` 规范化上下文资产系统（包含 `PROJECT.md`、`ARCHITECTURE.md`、`STATE.md`、`TASK.md`、`PLAN.md`、`DECISIONS.md`、`ISSUES.md` 与 `sessions/`）。
- 理由 (Reason):
  1. 纯 Markdown 文件持久化，完全与模型、IDE 和外部平台解耦；
  2. 确立“最小有效上下文”与“恢复测试五问”，实现毫秒级恢复工程上下文；
  3. 为架构决策与技术变动提供审计追踪链。
- 备选方案 (Alternatives):
  - 方案 A：依赖 IDE 本地会话历史或聊天记录缓存。放弃理由：跨会话易断层、无法随 Git 同步、难以让不同 AI 平台无缝复用。
  - 方案 B：仅维护单个 README 或单个无结构文档。放弃理由：信息混杂，职责不分明，极易产生上下文膨胀或遗漏硬约束。
- 影响 (Consequences):
  - 收益：每次任务交接标准规范，杜绝越权修改；
  - 约束：会话收尾需按规范同步更新 `STATE.md`、`TASK.md` 并沉淀会话。

## DEC-002 — 融合上游 1.29.2 主线并完整保留 Inverstar 本地定制特性

日期: 2026-10-18 | 状态: Accepted

- 确认来源: Git Commit `420af57` 与 `67cdef1`
- 背景 (Context): 上游 LifeOS 发布了 1.29.2 版本，包含了普通主题笔记、快速记录实时预览、10 种语言工作区等大量重要更新；而 Inverstar 分支在此前维护了特有的多级递归子目录扫描、层级标签（如 `#AI` 匹配 `#AI/agent`）深度筛选及 `isArchived` 归档状态过滤等业务特性。
- 决策 (Decision): 在合并 upstream 1.29.2 时，主动对冲突文件（如 `Archive.ts`、`File.ts`、`CreateNote/index.tsx`、`locales/`）进行双向融合，将 Inverstar 的递归搜索与层级标签逻辑整合进 1.29.2 架构中。
- 理由 (Reason):
  1. 既能全面享受上游生态的最新成果与用户体验优化；
  2. 又能完整保留定制化工作流的深度组织能力，避免定制特性被冲掉。
- 备选方案 (Alternatives):
  - 方案 A：完全丢弃本地定制，直接切回纯 upstream。放弃理由：违背本地用户的实际工作流需求，造成已有笔记索引失效。
  - 方案 B：永远停留于 1.27.0 定制版本，不上移。放弃理由：无法使用主题笔记、原生快速记录及多语言工作区等核心新特性，维护成本高。
- 影响 (Consequences):
  - 收益：成功获得 1.29.2 全部新特性与 101 项测试通过；
  - 约束/代价：未来合入 upstream 新版时需要针对定制逻辑执行冲突核验；需要为定制逻辑补充独立测试用例。

## DEC-003 — 建立只读预览与差异比对安全防护机制

日期: 2026-10-15 | 状态: Accepted

- 确认来源: Git Commit `5151e14` / `docs/releases/1.29.2.md`
- 背景 (Context): 插件版本升级（如主题查询结构升级、模板更新）时，若由程序静默重写文件，可能误伤用户手写笔记、反思段落或破坏自定义代码块。
- 决策 (Decision): 凡涉及用户现有笔记的大规模格式迁移或查询重构（如 `ThemeUpgradeModal`），必须先基于 `upgrade-plan.ts` 生成差异对比（Diff Preview），供用户逐项核验确认后再进行原子局部替换；未确认的区块严禁擅自改动。
- 理由 (Reason): 数据资产是笔记软件的根本，安全永远高于自动化的便利性。
- 备选方案 (Alternatives):
  - 方案 A：后台检测版本后静默自动升级。放弃理由：极度危险，一旦出现解析失误将导致用户数据损坏。
- 影响 (Consequences):
  - 收益：用户对笔记变更完全掌控，实现零数据丢失风险；
  - 约束：需要额外维护对比弹窗与升级解析规划逻辑。

## DEC-004 — 坚持 Local-First 与纯开源边界，不包含 Pro 闭源或遥测代码

日期: 2026-10-07 | 状态: Accepted

- 确认来源: `README-ZH.md` / `docs/pro-handover.md`
- 背景 (Context): 社区版与商业/独立 Pro 插件共存时，开源用户最关心数据隐私、是否有流氓广告或暗藏付费门槛。
- 决策 (Decision): 本仓库坚持 Local-First 原则，完全免费且保持纯净。严禁引入任何 Pro 版闭源实现代码、网络激活逻辑或第三方数据遥测跟踪；设置页仅保留静态只读说明与外部文档直达链接。
- 理由 (Reason): 保护开源声誉，严格捍卫用户离线数据的绝对隐私。
- 备选方案 (Alternatives): 引入远程授权验证与使用统计。放弃理由：严重违背开源宗旨与 Obsidian 社区插件安全准则。
- 影响 (Consequences): 保持插件体积轻量、安全纯粹。
